# l3-firewall

A **Layer 3 firewall sidecar** that intercepts, inspects, and filters IP packets using OPA/Rego policy-as-code. Built entirely in Go with zero cgo dependencies.

```
        ┌───────────┐  NFQUEUE   ┌──────────────┐  rules  ┌─────────┐
 Client ─▶  nftables │  queue     │  l3-firewall  │◀───────▶│  OPA    │
        │  QUEUE    │───────────▶│  sidecar      │  eval   │ Embedded │
        │  rule     │  verdict   │  (userspace)  │         │(in-proc) │
        └───────────┘            └──────────────┘         └─────────┘
```

## Attack Coverage

l3-firewall's OPA Rego policies cover **17 attack categories** with **399 Go tests** and **76 Rego tests** plus **28 demo tests** across 16 internal packages and 12 standalone demos. All packages are **terminally hardened** — red-team rounds 17–37 confirmed zero new vulnerabilities across all 5 target packages (syncer, l2filter, persist, capture, threatintel) and their integration points; round 38 hardened the remaining engine integration points (audit, alert, geoip); round 39 hardened the engine's conntrack integration point (unbounded port-scan map); round 40 hardened the last zero-coverage hot-path packages (ratelimit, metrics) and the engine's parse-error fail-open path; round 41 closed the R40.1 key-space propagation gap in l2filter's ARP table (IPv4-mapped key split + ARP-spoof alias bypass) and made threatintel's `Remove()` version-independent; round 42 closed the last open-file hardening classes in the 5-package integration surface — `--opa-embed` FIFO startup hang + oversized policy file, and symlink write-through on both `persist.SaveState`'s `.tmp` create and `capture`'s pcap rotation-file create; round 43 propagated the R42 symlink write-through class to the last remaining CREATE open — `audit`'s log file (O_NOFOLLOW); round 44 gave the metrics package its first-ever tests and closed its last two gaps — `Init()` double-call process crash (sync.Once idempotency) and the metrics HTTP server's missing `ReadTimeout`/`WriteTimeout` (admin parity); round 45 closed the directory-symlink write-through class (O_NOFOLLOW protects only the final path component — a symlink planted at the DIRECTORY path of `persist.SaveState`, `capture.NewWriter`, or `audit.NewLogger` redirects every write into an attacker-chosen directory as the firewall's UID; new `internal/securepath` helper walks every path component) plus two further vectors in the 5 target packages — threatintel CIDR duplicate accumulation across refreshes (unbounded `nets` growth filling the cap with duplicates and silently dropping new threats, fixed with canonical-form dedup) and l2filter DHCP empty-MAC binding poisoning (a MAC normalizing to empty stores `""` as the IP binding and DoS's the victim with false ARP-spoofing alarms, fixed by rejecting empty-normalized MACs in `RecordDHCP`); round 46 closed the two findings R42 documented but never fixed — the admin API `policyVersions` data race (concurrent `/admin/policy/reload` append vs `/admin/policy/versions` read, remotely triggerable when no admin tokens are configured; round 47 cleared the repo-wide lint debt (28 findings across 9 files: OPA v0→v1 import migration, `nf.Register` deprecation, 6 production errcheck, S1039, 19 test-file findings) — `make lint` is green for the first time since before R33; round 48 re-verified terminal status at the post-reformat HEAD; **round 49 found and fixed the deepest integration flaw to date** — the engine's NFQUEUE hook **never sent a verdict to the kernel**: go-nfqueue v1.3.2's hook return value is receive-loop control (`if ret := fn(m); ret != 0 { return }`), not the verdict, so the kernel was never told to accept/drop any packet (the queue saturated at 1024 and all traffic was dropped — total outage, the deny-override allow-by-default model could never allow anything) and the **first blocked packet terminated the receive loop permanently**. Fix: `handleQueuePacket` delivers every decision via `nf.SetVerdict(*attr.PacketID, NfAccept/NfDrop)` and returns 0 to keep the loop alive (loop stops only when a verdict genuinely cannot be delivered). Also fixed the **nil-payload fail-open sibling** of the R40 parse-error fix (an uninspectable packet was accepted; now dropped fail-closed) and added a startup warning for the **dead `--queue-input` flag** (parsed and logged but never wired into `eng.Run` — input traffic was never firewalled, an R40.4-class silently dropped control); round 50 closed the engine's cross-goroutine race class (stats counters → `atomic.Int64`, `running` flag → `atomic.Bool`, `ctx`/`cancel` lifecycle → `lifecycleMu` — all remotely triggerable via the unauthenticated admin API); **round 51 found and fixed 2 vulnerabilities in previously-exercised packages** — the admin API's read-token-only config bypassed auth entirely (`tokenMatches` matched any token when the admin token was unset — any network peer could read `/admin/stats`/`/admin/blocks`/`/admin/policy/versions` and POST `/admin/policy/reload` with a fabricated token; fixed by making unconfigured credentials never match, with the both-tokens-empty early-return as the ONLY auth-disabled path) and the **syncer watch-goroutine panic on a malformed etcd event** (nil-Event/nil-Kv wire shapes crashed the whole process — fixed by skipping malformed watch events with a warning); **round 52 found the R51 nil-shape class in the syncer's OTHER etcd path** — `loadCurrent`'s initial `Get` dereferenced `resp.Kvs[0].Value` with no nil-element check, so a GetResponse whose Kvs contains a nil KeyValue (or a nil response with nil error) panicked **synchronously on the main goroutine** inside `Start()` (no recover anywhere: main → Start → loadCurrent) — a startup crash DoS on the same malicious-etcd/MITM threat model R51 fixed in the watch loop. Fix: nil-response/nil-Kv-element guard with a warning, mirroring the R51 watch-loop pattern; round 53 re-verified terminal status at `1fb4866`; **round 54 found and fixed 2 vulnerabilities in previously-exercised packages** — the syncer's `Close()` was idempotent only for the stop channel (a second `Close()` re-invoked `client.Close()` on the R46 `etcdClient` interface, whose contract makes no idempotency promise), and threatintel's feed parser aborted the ENTIRE parse when one line exceeded the 1MB token cap (a malicious/compromised feed needed one 2MB line to permanently kill every refresh — new threats silently never added); also moved the syncer's `maxPolicySize` check BEFORE the value's string conversion in both `loadCurrent` and `watch` (check-before-allocate doctrine, R42/R13 class); **round 55 found and fixed 2 vulnerabilities in the 5 target packages (R38 FIFO class applied to CREATE opens — the R43 "one class's flag does not satisfy the other" lesson in reverse)** — R42's O_NOFOLLOW hardened persist's `.tmp` and capture's rotation-file CREATE opens against the SYMLINK class only: opening an existing FIFO planted at the fully predictable `state.json.tmp` or next `blocked_%05d.pcap` filename O_WRONLY without O_NONBLOCK BLOCKS until a reader appears — `SaveState`'s 60-second ticker hang stopped the same tick's `conntrack.Expire()`/`ratelimit.Cleanup()` (flow table fills → new connections blocked) and `WriteBlock`'s hot-path hang stalled the NFQUEUE receive loop (queue fills → kernel drops ALL traffic). Fix: `syscall.O_NONBLOCK` on both CREATE opens (the R38 audit pattern) — FIFO open fails immediately with ENXIO (logged error path), regular files unaffected. **Round 56 fixed a flaky test-side race in `internal/admin` (Go 1.25's `Serve` runs HTTP/2 auto-configuration asynchronously and raced the tests' `srv.TLSConfig == nil` read — rewritten behaviorally) and restored the missing R54 table row. Round 57 found and fixed the R45 guard's '..' bypass — `securepath.RejectSymlinkComponents` pre-Cleans '..' lexically BEFORE the walk, so a symlink planted at a component before a '..' (e.g. `/base/evil/../state` with evil → /victim) is walked as `/base/state` while the kernel resolves the raw path through the symlink: MkdirAll and every subsequent file open escape to the attacker-chosen directory while the walk passes. capture.NewWriter relied solely on the walk, and audit.NewLogger was worse — `filepath.Dir(cfg.Path)` strips '..' before the helper is even called while openAuditFile opens the raw path. Fix: reject '..' components in securepath on the RAW input (before Clean) + a persist-style path guard in audit.NewLogger. Round 58 found and fixed the R45 dedup class's other half in threatintel — the distinct-CIDR count was still unbounded up to the 500k total cap (ips+nets counted jointly), and `Contains()` scans the whole `nets` slice on EVERY hot-path packet: one feed fetch from a malicious/compromised server (the R54/R45 threat model) filling 500k distinct networks made each packet pay a ~4.7ms linear scan (measured), stalling the single-goroutine NFQUEUE receive loop and dropping ALL traffic. Fix: separate `maxCIDRNetworks` (65536) cap on the distinct-network slice — exact IPs stay O(1) with the full budget, only the O(n) scan path is bounded (~0.8ms worst case).**

```
                                  └── audit.Log() → JSON file (block/allow events)

Admin API (:8082)
  ├── /admin/health     → {"status":"ok","version":"0.1.0","uptime":"...","engine_running":bool}
  ├── /admin/stats      → {"packets_processed":N,"packets_allowed":N,"packets_blocked":N,
  │                        "conntrack_entries":N,"conntrack_expired":N,"conntrack_evicted":N}
  ├── /admin/blocks     → [{timestamp,src_ip,dst_ip,protocol,src_port,dst_port,reason,...}]
  ├── /admin/block-stats → {"blocked SSH": 42, "SYN flood": 7, ...}
  ├── /admin/policy/reload → Trigger policy hot-reload (POST)
  ├── /admin/policy/versions → Policy reload history
  └── State + pcap files on disk

Metrics (:9090 or admin port)
  └── /metrics → Prometheus format
```

### Key Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| **Interception** | NFQUEUE via `florianl/go-nfqueue` | Pure Go, kernel-level filtering, container-compatible with `CAP_NET_ADMIN` |
| **Packet Parsing** | `google/gopacket` | Well-established, comprehensive protocol support |
| **Policy Engine** | OPA embedded (in-process) | ~10µs eval, testable policies with `opa test`, same pattern as gql-firewall |
| **Security Model** | Deny-override | Traffic passes by default, blocked only by matching deny rules |
| **Rate Limiting** | EWMA-based PPS/BPS | Smooth rate estimation, no sudden drops |
| **Connection Tracking** | 5-tuple flow table | Stateful inspection for TCP state violations |

## Quick Start

### Prerequisites
- Go 1.25+
- OPA 1.0+ (for policy testing: `opa test opa-policies/`)
- Linux with nftables (for NFQUEUE runtime)
- Container: `--cap-add=NET_ADMIN`

### Build & Test

```bash
# Build
make build

# Run all Go and Rego tests
make test

# Run Go tests only
make test-go

# Run Rego tests only
make test-opa

# Lint and vet
make lint
make vet
```

### Run (Development — No NFQUEUE)

```bash
# Start just the admin API for testing (engine will log NFQUEUE error)
./l3-firewall --admin-listen :8082
```

### Run (Container)

```bash
docker build -t l3-firewall:latest .
docker run --cap-add=NET_ADMIN --rm -p 8082:8082 l3-firewall:latest
```

The entrypoint (`deploy/entrypoint.sh`) configures nftables to QUEUE forward and input traffic, then starts the firewall binary.

## Security Features

| Feature | Mechanism | What it prevents |
|---------|-----------|------------------|
| Admin API auth | `--admin-token` | Unauthorized rule changes |
| OPA fail-closed | `--opa-fail-closed` | Bypass via OPA DoS |
| Audit-only mode | `--opa-audit-only` | Safe data collection before enforcement |
| Deny-override model | Default `allow := true` | Safe phased rollout |
| Rate limiter map cap | MaxEntries eviction (oldest-first) | Memory exhaustion from unique IPs |
| Block stats reason cap | 256 unique deny reasons max | Memory exhaustion from reason flooding |
| Engine panic recovery | defer/recover in packetHandler + evaluatePacket | Process crash from unexpected panics |
| Configurable OPA timeout | EmbedConfig.Timeout (0=500ms default) | Workload-specific timeout tuning |
| TCP FSM tracking | 9-state machine (SYN→ESTABLISHED→FIN→CLOSED) | Connection state violation, evasive handshakes |
| Fragmentation detection | Parse IPv4 FragOffset + MoreFragments | Fragment-based evasion (overlap, tiny fragment) |
| CIDR subnet matching | `net.cidr_contains` | Real subnet filtering (not string match) |
| Port ranges | `port_in_ranges()` helper | Range-based rules (e.g. `"8000-9000"`) |
| Per-protocol timeouts | TCP=300s, UDP=30s, ICMP=5s | Optimal memory usage per protocol |
| Drop logging | Structured slog + ring buffer | Forensic analysis of blocked traffic |
| Recent-blocks API | `/admin/blocks` | Real-time visibility into blocks |
| Conntrack stats | `/admin/stats` | Monitoring connection table health |
| Engine health | `/admin/health` endpoint | Liveness and readiness probes |
| Bodies size limit | `http.MaxBytesReader` | Admin API OOM |
| Server timeouts | `ReadHeaderTimeout`, `IdleTimeout` | Slow loris / connection exhaustion |
| Graceful shutdown | Signal handling + context cancellation | Dropped connections on deploy |
| Per-IP rate tracking | EWMA-based PPS/BPS | Memory-efficient rate estimation |
| Connection limit | Per-source flow counter capped by `MaxFlowsPerSrcIP` | DoS via excessive concurrent connections |
| Time-based scheduling | `time_based_rules` in Rego policy with UTC hour/day | Access outside approved hours |
| Audit logging | `--audit-log` writes structured JSON | SIEM integration, compliance audit trail |
| Webhook alerts | `--alert-webhook-url` fires JSON POST on events | Real-time incident notification |
| GeoIP filtering | `--geoip-db` + Rego `blocked_src_countries` / `allowed_src_countries` | Country-based access control |
| Threat intel feeds | `--threat-intel-url` fetches IP blocklists | Known-bad-IP blocking |
| MAC filtering | `--mac-allow` / `--mac-block` + L2 filter | MAC spoofing, unauthorized devices |
| Unicode MAC normalization | `strings.Fields()` strips all Unicode whitespace | MAC filter bypass via NBSP, thin space, etc. |
| ARP/DHCP inspection | IP→MAC binding table, change detection | ARP spoofing, DHCP poisoning |
| Packet capture | `--pcap-dir` writes blocked packets to pcap | Forensic analysis |
| State persistence | `--state-file` saves block stats to JSON | Survive restarts without losing counters |
| State persistence size limit | `io.LimitReader` (10MB) in LoadState | Memory exhaustion via malicious state file |
| Policy versioning | `/admin/policy/versions` endpoint | Audit trail for rule changes |
| Distributed sync | `--etcd-endpoints` watches etcd for policy updates | Multi-instance rule consistency |
| etcd watcher panic recovery | `safeOnUpdate()` wrapped around all callback calls | Goroutine death from onUpdate panic in syncer |
| Threat feed body limit | `io.LimitReader` (50MB) on FetchFromURL resp.Body | Memory exhaustion via malicious feed server |
| Nil block stats guard | Auto-initialize `BlockStats` map in LoadState | Nil map panic on state reload |

```rego
mock_params := {"enable_ip_spoofing_check": false}
```

## Performance

- **Packet parsing**: ~1µs per packet (gopacket, cached layer types)
- **OPA evaluation**: ~10µs per packet (in-process, prepared query)
- **Connection lookup**: O(1) hash map with RWMutex
- **Rate limiting**: O(1) EWMA update
